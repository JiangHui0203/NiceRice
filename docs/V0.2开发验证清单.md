# V0.2 开发验证清单

## 本阶段目标

- 推荐结果由统一 recommendation engine 生成。
- 首页、券详情、券包排序、计划确认共用同一推荐结果。
- 推荐可以生成计划，计划可以查看、改时间、取消、完成和反馈。
- 内置样例计划第一次被操作时应转为本地可编辑计划，不再出现“示例计划不可操作”的开发提示。
- 券规则、预约、退款/损失风险进入推荐判断。
- 添加/编辑券可以选择真实地点，并把地点数据保存为后续路线估算的输入。
- 路线估算通过云函数代理，未配置地图 Key 时可以降级为手动填写路程。
- 截图 OCR 通过云函数代理，未开通 OCR 时可降级为粘贴识别/手动添加。
- 推荐规则应把临期、过期损失、不可退款、预约截止、营业时间、天气和清洁风险纳入评分。
- 推荐结果必须早于或等于券过期日，不能把临期券安排到过期后。
- 计划邀请、朋友确认/拒绝、计划变更提醒应有本地和云端占位链路。
- 计划页提供「今天吃啥」转盘，可以在纯随机和权重随机之间切换，候选项来自待用券和手动添加。
- 「今天吃啥」转盘可以按候选来源和大类筛选参与池，大类包括美食、饮品、娱乐、户外、生活等。
- 我的页可以本地维护固定不可用日程，推荐应自动避开这些时间。
- 我的页可以本地维护常用出发地点和地图点，默认加密保存，并作为添加券页路线估算的优先起点。
- 我的页可以查看和切换隐私模式；默认本地保护，不上传截图、位置或计划数据。
- 我的页可以手动切换当前天气，用于在未接真实 API 前验证天气推荐规则。

## 核心验证指标

- 添加券完成率：进入添加页后是否能保存成功。
- 推荐采纳率：看到推荐后是否点击加入计划。
- 计划确认率：生成计划后是否确认或邀请朋友。
- 计划完成率：计划是否最终标记完成。
- 推荐反馈率：完成后是否提交推荐反馈。

## 固定测试场景

- 明天过期的粉面券：应优先、适合午餐、无额外清洁压力。
- 3 天后过期的火锅券：应提示味道大、洗澡洗头、预约。
- 雨天公园票：应产生户外天气风险。
- 路程过远的烧烤券：应提示路程风险。
- 需要预约且快过期的双人券：应提示预约风险。
- 用户忌口冲突：应阻断或降低推荐。

## 数据约定

- 券统一使用 `expireDate`、`category`、`tags`、`usageRules`、`refundInfo`、`reservationStatus`。
- 地点统一使用 `location.name`、`location.address`、`location.latitude`、`location.longitude`、`location.source`。
- 路线统一使用 `route.source`、`route.distanceText`、`route.durationMinutes`、`route.distanceMeters`。
- 推荐统一使用 `score`、`level`、`recommendedTime`、`reasons`、`warnings`、`blockers`、`scoreBreakdown`。
- 计划统一使用 `statusCode`、`selectedTime`、`participants`、`recommendationSnapshot`、`liveRisk`、`feedback`、`inviteId`。
- 本地 schema 当前版本：`2`。
- 用户敏感本地数据统一通过 `privacyService.readLocalData/writeLocalData` 加密保存。
- 常用地点统一通过 `locationPreferenceStore` 保存，默认包含学校/公司、家、朋友常用点，并支持 `latitude`、`longitude`、`source`、`selectedAt`。
- 截图附件默认保存为本地加密文件，券数据中只保存加密文件引用。

## 异常与隐私边界

- 券不存在、计划不存在、推荐为空时必须 toast 或空状态兜底。
- 好友只共享可约时间和必要偏好，不展示完整日程。
- 天气当前支持本地样例和手动覆盖；路线、OCR、订阅消息发送和邀请云同步默认受隐私模式拦截，不上传用户数据。
- 只有用户在“我的-隐私”中明确开启云端增强后，路线估算、截图 OCR、云端邀请同步和订阅消息发送才会调用云函数。
- 位置选择必须由用户主动点击触发；保存经纬度前要让用户看到地点名称和地址。
- 订阅消息模板 ID 可以在调试页本地配置，真实发送前必须确认模板来源和用途。
- 未配置云环境 ID 时不得主动初始化云能力；OCR、路线、邀请同步和订阅发送应给出明确占位提示，不能在启动或操作时长期超时。

## 转盘功能验证

- 从计划页进入「今天吃啥」页面。
- 默认候选项应包含可用券和几个手动候选项。
- 关闭某个候选项后，转盘不应抽中它。
- 切换来源或大类筛选后，转盘只在当前筛选结果里抽取。
- 纯随机模式下，每个启用候选项机会相同。
- 权重随机模式下，临期、高适合度、低风险券更容易被抽中。
- 抽中券后可以进入计划确认页。
- 抽中手动项后可以生成临时计划，并进入计划详情页。
- 手动添加候选项可以保存、显示和删除。

## 发布前检查

- `app.json` 页面路径完整。
- JS 语法检查通过。
- JSON 语法检查通过。
- 添加券页选择地点、手动地址、手动路程三种路径都能保存。
- 券详情和计划详情应展示位置卡；有经纬度时显示地图点，没有经纬度时显示路线摘要和补点提示。
- 添加券页未部署云函数/未配置 Key 时，点击估算应给出明确提示。
- 添加券页未开通 OCR 时，点击截图识别应给出明确提示。
- `app.js` 云环境 ID 为空时，开发者工具控制台不应因为自动云初始化产生启动 timeout。
- 我的页常用地点编辑、地图选点、取消、保存、恢复默认应能正常工作。
- 添加券页路线估算应优先读取默认常用起点；常用起点缺地图点时，应提示并降级为临时当前位置。
- 调试页订阅模板可以保存、清空，并被 `notificationService.getTemplateIds()` 读取。
- 朋友邀请分享链接可以带上 `inviteId`，并能读取计划快照。
- 朋友确认/拒绝后，发起人再次打开计划详情应能同步状态。
- 已邀请计划改时间后，应更新原邀请快照，不应无条件生成新的邀请链接。
- 计划详情页底部操作应保持「主按钮 + 更多」分层，展开更多操作后内容仍能正常滚动，不被按钮区域遮挡。
- 大于 200K 的非必要图片/音频资源应压缩、移出主包或放 CDN。
- 体验版测试时按固定测试场景逐项走一遍。
