# 公共服务 API 接入路线

## 目标

把当前本地 MVP 逐步升级成可真实使用的小程序能力，但不让第一版被平台接入拖重。近期重点是：

- 地点选择和位置保存。
- 天气数据替换本地 mock。
- 路线时间估算。
- 计划与券过期订阅提醒。
- 截图 OCR 和券规则解析。

美团、抖音、大众点评等平台的真实订单和券包读取暂不作为第一阶段依赖。

## 接入原则

- 页面只调用项目内的 service，不直接写第三方 API 细节。
- 天气、地图、OCR、订阅消息等外部能力先走 mock、手动覆盖或本地占位，再替换真实服务。
- API key、AppSecret、第三方密钥不放在小程序前端。
- 真实网络请求必须走 HTTPS，并在小程序后台配置 request 合法域名。
- 涉及位置、订阅消息、OCR 的能力要在用户主动操作时触发，并说明用途。
- 多人协同只共享可约时间和必要偏好，不暴露完整日程。
- 默认使用本地保护模式；路线、OCR、订阅发送和邀请云同步必须在用户明确开启云端增强后才允许上传必要数据。

## 微信小程序官方能力

| 能力 | 推荐优先级 | 用途 | 当前处理 |
| --- | --- | --- | --- |
| `wx.request` | P0 | 请求后端、云函数、天气、地图、OCR | 待封装统一 request service |
| `wx.setStorageSync` / `wx.getStorageSync` | P0 | 保存券、计划、偏好、推荐反馈 | 已封装到 `privacyService`，敏感数据默认加密 |
| `wx.chooseLocation` | P0 | 添加券时选择店铺位置 | 已接入，用户主动点击后保存名称、地址和经纬度 |
| `wx.getLocation` | P1 | 用户主动请求实时 GPS | 保留为可选能力；默认起点改为用户主动使用 `wx.chooseLocation` 选点 |
| `wx.chooseLocation` | P0 | 首页和添加券时选择地点 | 直接使用微信地图返回的名称、地址和经纬度，不占用项目自己的腾讯位置服务 Key 配额 |
| `map` 组件 | P2 | 券详情和计划详情展示目的地 | 已接入详情页；无经纬度时显示路线摘要和补点提示 |
| `wx.requestSubscribeMessage` | P1 | 券过期、计划出发、朋友确认提醒 | 已有授权服务和调试页模板配置，真实发送需要模板 ID 和云端增强 |
| OCR / 云调用 | P2 | 截图识别券信息 | 已有截图识别入口和云函数链路，默认隐私模式下不上传 |

## 第三方公共服务

| 能力 | 推荐服务 | 用途 | 说明 |
| --- | --- | --- | --- |
| 天气 | 腾讯位置服务 / 高德 / 百度 | 雨天、晴天、温度对推荐加权 | 当前支持手动天气覆盖；真实接入建议和地图服务尽量同源 |
| 地理编码 / 逆地理编码 | 腾讯位置服务 / 高德 / 百度 | 地址转坐标、坐标转附近街道或 POI | 当前逆地理编码支持腾讯位置服务，优先由 `lifeServices` 云函数代理 |
| 路线规划 | 腾讯位置服务 / 高德 / 百度 | 估算自己和朋友到店时间 | 推荐引擎只消费统一后的 `durationMinutes` |
| OCR | 微信 OCR / 腾讯云 OCR / 百度 OCR | 识别截图中的商家、日期、地址、规则 | OCR 后必须让用户确认再保存 |
| 云函数 / CloudBase | 微信云开发 / 腾讯云 | 代理密钥、发订阅消息、同步计划 | 后续真实协同需要 |

## 平台券包 API 边界

美团、抖音、大众点评等平台可能提供团购券、核销、订单相关接口，但这些能力通常面向商家、服务商或平台内经营者，并不等于普通微信小程序可以读取用户个人券包。

第一阶段更现实的入口是：

- 手动添加。
- 粘贴文字识别。
- 截图 OCR。
- 分享链接/文本解析。

平台自动读取不进入 V0.2 和 V0.3 的关键路径。

## 建议接入顺序

1. `wx.chooseLocation`：添加券时选择地点，保存名称、地址、经纬度。
2. 路线 service：先统一 route 数据结构，继续允许手动填写路程。
3. 天气 service：当前支持手动覆盖；后续把本地天气替换为真实城市天气。
4. 订阅消息：券快过期、计划出发、朋友未确认三类模板。
5. 云函数代理：隐藏地图、天气、OCR、订阅消息密钥。
6. OCR：截图识别券文字，再进入规则解析和用户确认。
7. 好友邀请：计划确认、改时间、完成反馈的共享链路。

## 当前隐私默认

当前小程序默认采用本地保护模式：

- 本地敏感数据通过 `privacyService.readLocalData/writeLocalData` 加密保存。
- 新增券截图默认保存为本地加密附件。
- OCR 不会默认上传截图。
- 路线估算不会默认上传当前位置和店铺位置。
- 订阅消息发送不会默认把计划内容提交到云函数。
- 邀请创建会先生成本地邀请，云端同步只作为增强能力。

用户可以在“我的-隐私”里开启云端增强。开启后，路线估算、截图 OCR、邀请云同步和订阅消息发送才会走 `lifeServices` 云函数。

如果 `app.js` 还没有配置云环境 ID，小程序不会主动初始化云能力；所有云端增强入口会给出“云环境未配置”的明确提示，并继续保留本地占位流程，避免开发阶段出现无意义的云调用超时。

## 本阶段地点能力

本阶段先做轻量闭环：

- 添加/编辑券页增加“选择位置”按钮。
- 使用 `wx.chooseLocation` 获取店名、地址、经纬度。
- 保存时把 `location` 写入券数据。
- 路程仍支持手动填写；如果已经选择位置但没有路程，显示“待估算”。
- 添加/编辑券页增加“估算”按钮，由用户主动触发当前位置授权。
- 路线估算通过 `lifeServices` 云函数代理，地图 Key 不进入小程序前端。

目标不是马上做导航，而是让每张券具备可靠的地点数据。

## 路线估算接入

当前已经预留并接入这条链路：

```text
添加/编辑券页
↓
locationService.getCurrentLocation
↓
routeService.estimateRouteByLocation
↓
wx.cloud.callFunction({ name: "lifeServices", type: "estimateRoute" })
↓
腾讯位置服务 / 高德地图
↓
统一 route 数据写回券表单
```

云函数路径：

```text
cloudfunctions/lifeServices
```

默认使用腾讯位置服务。部署云函数后，在云函数环境变量中配置其中一个：

```text
TENCENT_MAP_KEY
QQ_MAP_KEY
```

首页自动定位需要逆地理编码能力。云函数已支持：

```text
lifeServices -> reverseGeocode
```

如果云环境未配置，前端只有在用户明确保存了自己的地图 Key 后才会尝试直连腾讯位置服务；没有 Key 时只使用本地定位/测距兜底，并显示“附近位置未解析”，不会用城市中心或估算区域冒充用户附近地点。项目不再内置公共演示 Key，避免开发调试时在后台持续消耗第三方调用次数。

如果要改用高德，调用时把 provider 改为 `amap`，并配置其中一个：

```text
AMAP_MAP_KEY
GAODE_MAP_KEY
```

高德公交路线通常还需要城市信息，第一阶段建议优先用腾讯位置服务，和微信生态更顺。

未配置 Key、云函数未部署、用户拒绝位置权限时，前端会降级为手动填写路程。

在本地保护模式下，点击“估算”会直接提示手动填写，不会先请求当前位置权限。

在云端增强已开启但云环境 ID 未配置时，路线估算会提示先配置 `app.js` 的云环境 ID 并部署 `lifeServices`，不会继续等待云函数超时。

## OCR 接入

当前推荐采用这条路径：

```text
添加/编辑券页
↓
选择优惠券截图
↓
用户开启云端增强后上传到云存储
↓
lifeServices 云函数
↓
微信 OCR / 后续腾讯云 OCR
↓
返回文字
↓
本地规则解析并回填表单
```

本阶段已经在添加券页接入“截图识别”按钮，并在 `ocrService` 中封装：

```text
chooseMedia / chooseImage
cloud.uploadFile
cloud.callFunction({ name: "lifeServices", type: "recognizeCouponImage" })
```

云函数会优先尝试 `cloud.openapi.ocr.printedText`。如果当前云环境未开通 OCR，会返回明确提示，前端继续保留“粘贴识别”和“手动添加”。

如果用户未开启云端增强，点击“截图识别”会提示 OCR 已保护；用户仍可以用“添加截图”把券截图作为本地加密附件保存和预览。

如果用户开启云端增强但尚未配置云环境 ID，截图识别会提示先完成云环境和 `lifeServices` 部署，不会上传截图或进入超时等待。

轻量本地 OCR 暂不建议作为小程序第一阶段方案：

- Tesseract / PaddleOCR 这类模型体积和运行成本偏高，容易影响小程序包体和低端机性能。
- 优惠券截图的难点不只是识别文字，还要解析日期、规则、门店、地址，云端更便于迭代。
- 端侧可以先做图片选择、压缩、裁剪和结果确认；识别本身走云函数更稳。

后续如果要替换成腾讯云 OCR，只需要在 `lifeServices` 里把 `recognizeCouponImage` 的 provider 换掉，前端不需要改页面。

## 订阅消息与提醒

当前已经预留：

- 计划出发提醒。
- 预约提醒。
- 朋友未确认提醒。
- 券过期提醒。
- 天气变化提醒。

前端通过 `notificationService.requestPlanSubscriptions(plan)` 请求用户授权；服务端通过 `lifeServices` 的 `sendSubscribeMessage` 发送。真实发送前需要在小程序后台申请模板，并在调试页写入本地模板配置，或后续迁移到云端配置：

```text
couponExpiring
planDeparture
friendPending
reservation
weatherChanged
```

注意：小程序不能偷偷推送，订阅消息必须由用户主动点击触发授权。

## 好友邀请与协同

当前已经预留并接入：

- 生成计划后创建邀请记录。
- 计划详情页可通过微信分享卡片邀请朋友。
- 朋友打开分享链接后可读取云端邀请快照。
- 朋友确认/拒绝会写回邀请记录。
- 发起人再次打开计划详情时会尝试同步邀请状态。

第一阶段这不是完整社交系统，但已经把“邀请、确认、拒绝、跨设备读取计划快照”的骨架搭好。

默认本地保护模式下，邀请不会写入云端；分享路径仍可生成，但跨设备读取和状态同步需要开启云端增强。

## 统一数据结构

地点：

```js
{
  name: "青禾铜锅",
  address: "某某路 88 号",
  latitude: 31.2304,
  longitude: 121.4737,
  lat: 31.2304,
  lng: 121.4737,
  source: "wx.chooseLocation",
  selectedAt: "2026-05-31T12:00:00.000Z"
}
```

路线：

```js
{
  source: "manual",
  distanceText: "28分钟",
  durationMinutes: 28,
  distanceMeters: null,
  transportType: "transit"
}
```

天气：

```js
{
  date: "2026-06-05",
  weather: "rain",
  weatherText: "小雨",
  temperature: 12,
  suitableScenes: ["火锅", "博物馆", "电影"]
}
```

## 小程序后台配置提醒

真实接入前需要逐项检查：

- request 合法域名：天气、地图、OCR、后端或云函数域名。
- 位置隐私声明：说明为什么要选择/获取位置。
- 订阅消息模板：过期提醒、计划出发提醒、朋友确认提醒。
- 云函数权限：避免把密钥放在小程序代码包里。
- 包体检查：大图片和音频继续放 CDN 或排除出主包。
