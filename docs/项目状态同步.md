# 项目状态同步

## 当前状态

- 项目是微信小程序本地 MVP，核心目标是把快过期的券安排到合适时间。
- 已完成主流程：添加券、券包排序、首页推荐、券详情、计划确认、计划详情、改时间、取消、完成和反馈。
- 推荐引擎已经统一供首页、券包、券详情、计划确认和本周安排使用。
- 推荐规则已纳入临期、过期损失、不可退款、预约提前量、可用时段、天气、路程、忌口、清洁和次日早安排。
- 计划页已加入“今天吃啥”转盘，支持纯随机/权重随机、来源筛选、大类筛选、手动候选和临时计划。
- 我的页已支持饮食偏好单独编辑、常用地点编辑和地图选点、朋友可约时间、固定不可用日程、手动天气和隐私设置。

## 隐私与本地数据

- 默认模式是本地保护，不上传截图、当前位置、店铺位置或计划内容。
- 券、计划、偏好、常用地点、朋友、日程、转盘、邀请和日志等本地敏感数据已统一加密存储。
- 新增截图默认保存为本地加密附件；页面只显示缩略图，点击后临时解密预览。
- 旧明文存储会在启动迁移时自动写回加密格式。
- 调试重置会清空本地数据、隐私密钥、隐私设置和本地截图缓存。

## 外部 API 状态

- 天气：真实 API 未接入；已支持在“我的页”手动切换小雨、晴天、多云、炎热、偏冷，用于验证推荐规则。
- 路线：前端和云函数链路已预留；添加券页会优先使用“我的页”常用地点作为默认起点，默认隐私模式下拦截上传，开启云端增强并配置地图 Key 后可估算。
- OCR：截图识别入口和云函数链路已预留；默认隐私模式下拦截上传，可继续用截图附件、粘贴识别或手动添加。
- 订阅消息：授权入口、发送服务和调试页模板 ID 配置已预留；真实发送还需要小程序后台申请模板。
- 好友邀请：本地邀请和分享路径已接入；改时间会更新已有邀请快照。跨设备同步需要云端增强和云函数。
- 云环境：`app.js` 未配置环境 ID 时不会初始化云能力；OCR、路线、邀请同步和订阅发送会提示未配置并保留本地占位，避免启动或操作时云调用超时。

## 当前仍未完成

- 没有真实天气 API；当前为手动天气覆盖和本地样例。
- 没有真实地图 Key 和线上路线估算验证。
- 没有配置真实微信云开发环境 ID；云端增强仍停留在占位提示和本地闭环。
- 没有真实 OCR 服务验证。
- 没有真实订阅消息模板和定时发送任务；调试页已能本地配置模板 ID。
- 没有完整账号体系，朋友确认仍是轻量共享链路。
- 没有自动读取美团、抖音、大众点评等平台个人券包。
- 微信模板示例页和无关教程图片已从项目中移除，主包资源只保留当前小程序需要的图标与业务文件。

## 下一轮建议

1. 先做天气服务接入或城市选择，把当前手动天气覆盖替换为真实城市天气。
2. 再做路线估算真实联调，补充地图 Key、云函数部署和失败兜底。
3. 然后申请真实订阅模板，并用调试页模板配置入口验证计划出发提醒。
4. 最后再接 OCR，因为 OCR 涉及图片隐私和识别质量，最好放在隐私策略稳定之后。

## 可发送给外部 ChatGPT 的同步消息

当前项目是一个微信小程序 MVP，用来把快过期的优惠券按时间、天气、路程、朋友可约、清洁习惯和个人偏好安排成计划。已完成本地闭环：添加券、券包、首页推荐、券详情、计划确认、计划详情、改时间、完成反馈、朋友可约、固定日程、常用地点和地图选点、手动天气、饮食偏好和“今天吃啥”转盘。推荐规则已经覆盖临期、价格损失、不可退款、预约风险、营业时间、天气风险、雨天路程、忌口、重口味清洁和次日早会。

隐私策略已经改成默认本地保护：券、计划、偏好、常用地点、朋友、日程、转盘、邀请和日志加密保存在本地；截图默认加密存本地，页面缩略图展示并可放大预览。OCR、路线估算、订阅消息发送和邀请云同步默认不会上传数据，只有用户在“我的-隐私”里明确开启云端增强后才会走云函数。

目前主要未完成是真实 API 接入：天气 API、地图路线 Key、OCR 服务、真实订阅消息模板、跨设备邀请同步和自动读取平台券包。订阅模板 ID 已经可以在调试页本地配置。下一步建议把手动天气升级为真实天气，或者先联调路线估算；OCR 放后一点更稳。
